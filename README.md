#### 一次性迁移所有网站的本地存储和数据库（IndexedDB，含文件）。

浏览器没有给插件"直接读取所有网站本地存储"的接口——只有跑在那个网站自己的页面里的代码才准碰它的数据。所以插件的做法是：在后台给每个网站立一个空壳页面，地址是它的、内容由本地现造，页面一立起来就能读写这块硬盘上的数据，读完就关。全程不向任何网站发一个请求，断网也能备份和恢复。

- 导出/导入 Cookies 与 导出/导入网站数据 是两套独立按钮，互不影响。
- 要处理哪些网站，来自三个来源：正在打开的标签页、有 Cookie 的域名、浏览历史；也可以自己粘一份网址清单（一行一条），两边会自动去重合并。
- 新加了"调试、读历史、读标签页"这几项权限，更新后要到扩展管理页点一次"重新加载"并同意授权。
- 干活时会另外开一个小窗口在后台跑，做完自己关掉，期间别手动关它。
- 导入是覆盖式的：备份里的键值会替换网站上同名键值；数据库先删再按备份重建，版本号、主键、索引、文件都会还原。
- 只管普通网站（http/https），浏览器自己的页面和扩展页面不在范围内；会话存储（关掉网页就消失那种）不迁移。
- 备份文件一个网站一行，人能看懂，也能用工具直接查。
- 什么都没存的网站不会写进备份；界面上会说清"扫了几个、其中几个真有数据"，不会拿空壳充数。
- 清单和失败记录都有量级保护：清单超过扩展存储上限（约 10MB）会明确告知而不是默默丢；失败详情最多留 200 条，总数照常报。
- 实测数据（临时独立浏览器，60 个网站各含 1MB 文件、备份 80MB）：导出每个网站约 40 毫秒；导入耗时 7.3 秒，内存峰值 114MB，约为文件体积的 1.4 倍（改成流式读取之前是 264MB、约 3.3 倍）。
- 备份格式换了版本，旧版导出的文件不能给新版用，插件会直接说明，不会半推半就地写坏数据。
