#### 一次性迁移所有网站的本地存储和数据库（IndexedDB，含文件）。

界面上这两样各有一个勾选框，默认只勾本地存储；要连数据库一起搬就勾上 IndexedDB。

浏览器没有给插件"直接读取所有网站本地存储"的接口——只有跑在那个网站自己的页面里的代码才准碰它的数据。所以插件的做法是：在后台给每个网站立一个空壳页面，地址是它的、内容由本地现造，页面一立起来就能读写这块硬盘上的数据，读完就关。全程不向任何网站发一个请求，断网也能备份和恢复。

#### 界面现在分两层：小入口 + 独立窗口

- 点图标出来的是一个小入口，只有一个"打开独立窗口"按钮。真正干活的是那个独立窗口：它是单独一个窗口，鼠标点了别的地方不会缩回去，也不会被浏览器偷偷收掉。
- 为什么重活都放进独立窗口：浏览器规定"挑保存位置/挑文件"这一下必须由你亲自点，而小弹窗一眨眼就没了，事后再让它挑文件它已经不在了。旧版那种"跑完再弹保存框"就出过问题——框是弹在背后那个没人看的窗口上，你看不见，插件就一直干等，看着像卡死。
- 独立窗口里有进度条、有正在处理哪几个网站、有"中止"按钮，还有一块记失败详情的流水账。
- 网站数据要搬哪几样，由界面上两个勾选框说了算：**LocalStorage**（本地存储，网页自己记的小纸条）和 **IndexedDB**（网站数据库，里面的记录和文件都算）。只勾一个就只读只写那一样，另一种碰都不碰；两个都不勾时点"导出网站数据"或"导入网站数据"不会开工，界面会说一句"至少勾一个"。这两个勾选也会记住，下次打开还是上回的选择（默认只勾 LocalStorage，要搬数据库得自己勾上 IndexedDB）。
- 干活期间关这个窗口，浏览器会先问你一句，免得跑一半白丢。

#### 速度（2026-10-15 实测，临时独立 Edge 档案）

- 扫描这一步新旧持平，没变快：600 个什么都没存的网站、同时干活 3 个页面，新版 29.9 秒（每秒 20 个、每个 50 毫秒），旧版 27.8 秒（每秒 21.6 个、每个 46 毫秒）。开一个网站空壳的固定开销是浏览器给的，这次压不掉。
- 小负载对照（120 个网址、15 个有数据、备份 12MB、并发 3）：新版导出 4.4 秒、页面内存峰值 16.4MB；旧版导出 3.8 秒、16.8MB。新版导入 2.0 秒，旧版导入 1.0 秒——这个量级上新版不比旧版快。
- 真正变的是内存的算法和中止/换页面的行为：
  - 处理完一个网站就当场写进文件，内存里最多同时攒"同时在跑的那几个网站"，不再跟整份备份一样大。
  - 网站空壳页面一段一段主动把数据推过来，不再一块一块去问；数据库一批一批捞（一批最多 500 条或 4MB），几百万条记录也压不垮页面。
  - 导入 Cookies 改成一小批 20 个一起写，不再一条等一条。
  - 数据不再从"处理页"转手：独立窗口自己就是干活的地方，中间那一跳整个省掉。
- 大数据上的一次现场记录：跑到人为中断前，连续写出 641MB 备份，进度从 100 个网站推到 3134 个，每 20 秒稳定推进约 130 个，全程没停过。
- **没测的**：500MB 级的新旧对照耗时与内存峰值（跑一次机器吃不住，决定不跑了）；真的"另存为"框在独立窗口里能不能弹出——脚本环境弹不出真框，只能你在真浏览器里点一次确认。

#### 不再"停在某个数字不动"（专项实测 6 项全过）

- 原来的失败模式：几个循环抢一个公共页面池，池子补充失败时某个循环就永远等不到页面，进度从此钉住，而且此后每次点都报"已经有任务在跑"。现在每个工作循环自己守一个页面，它只等自己手上的活，结构上堵不死。
- 干活途中关掉 1 个工作页面 → 照常跑完，只记 1 项没能处理（2.5 秒）。
- 干活途中把全部工作页面一次关掉 → 也照常收尾，记 3 项没能处理（2.3 秒），没有钉住。
- 按"中止" → 0.9 秒停下来，文件尾部写明这次没跑完，紧接着再点还能正常跑第二次。
- 网站页面被浏览器丢掉、调试连接被掐断、半天没吐数据：这三种都会立刻把那个页面判死、换新页面继续（每一步都有截止时间：进网站 20 秒、单条指令 60 秒、整站转储 5 分钟、两次数据推送之间 60 秒）。
- 独立窗口被误关之前浏览器会先问一句；没关的时候弹窗那边显示"独立窗口正在导出 320/6000"，点一下就跳过去。

#### 数据对不对（端到端实测 24 项 + 勾选框专项 16 项，全过）

- 导出 → 把这个网站的硬盘擦干净 → 导入 → 逐项核对：文件字节一块不少、字节校验和完全对得上（3 个 1.2MB 文件共 3686400 字节）。
- 数据库的版本号、三种主键形式（自带主键 / 外部主键 / 自增主键）、索引都还原；Map、Set、日期、正则、Int16Array、数组里的空位、嵌套对象都还原；键名和值里带换行、制表符也不串。
- 并发 3 个网站同时跑，其中一个网站的备份有 4.9MB 被切成十几段推送，结果仍然是一个网站一行、没串行。
- 什么都没存的网站不写进备份；Cookies 导出→删掉→导入，值和属性都回来；取消保存框时界面会说"已取消，没有写任何文件"。
- 这轮测出并修掉一个真问题：大文件分块转文字时每块都会补一个"="，拼起来就解不开码，导致存了大文件的网站数据库写不回去（现在分块大小取 3 的倍数）。
- 勾选框专项实测 16 项全过（三个网站：两样都有 / 只有本地存储 / 只有数据库）：只勾一样时备份里就完全没有另一样那一段，只有另一种数据的网站也不会被写进备份；只勾一样导入时另一种一行都不写；两个都不勾点按钮只提示、不开工也不弹保存框；拿只含本地存储的备份去只勾数据库导入，报"写回 0 个网站"而不是瞎写。
- 这一轮又测出并修掉一个真问题：只勾 LocalStorage 时，那一行少了收尾的括号，备份成了半成品（读的时候会报"网站地址不对"跳过）。现在括号跟勾选无关，一律补齐。

#### 其他要点

- 导出/导入 Cookies 与 导出/导入网站数据 是两套独立按钮，互不影响。
- 要处理哪些网站，来自三个来源：正在打开的标签页、有 Cookie 的域名、浏览历史；也可以自己粘一份网址清单（一行一条），两边会自动去重合并。
- 权限少了两项（下载、offscreen），也不再需要后台脚本；更新后要重新加载插件一次。
- 干活时工作页面开在一个最小化的窗口里，完事自动关掉，别手动去关它们。
- 导入是覆盖式的：备份里的键值会替换网站上同名键值；数据库先删再按备份重建，版本号、主键、索引、文件都会还原。
- 只管普通网站（http/https），浏览器自己的页面和扩展页面不在范围内；会话存储（关掉网页就消失那种）不迁移。
- 备份文件换成 v3 格式：第一行是版本号，之后一个网站一行，最后一行是这次的总结（扫了几个、写进去几个、失败清单）。一行一条所以能一行一行读，几百兆的备份不需要整份进内存；也能用工具直接查。
- 旧版导出的文件不能给新版用，插件会直接说明，不会半推半就地写坏数据。
- 什么都没存的网站不会写进备份；界面上会说清"扫了几个、其中几个真有数据"，不会拿空壳充数。勾了哪一样就按哪一样算：只勾 LocalStorage 时，一个只有数据库的网站照样算"没什么可写"，不会进备份。
- 清单和失败记录都有量级保护：清单超过扩展存储上限（约 10MB）会明确告知而不是默默丢；失败详情最多留 200 条，总数照常报。
- 可以调"同时干活的数量"（1 到 20，默认 3）：后台同时开几个页面一起搬，网站少时会自动少开，不会白占。这次只实测了并发 3，更高档没测，所以默认值不动。
